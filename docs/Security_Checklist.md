# Security Checklist & Audit Verification — SahanaMart

Anna University R2025 Semester 3 Capstone Deliverable (Week 7 & 8).
Evaluation criteria based on Section 9 Security Specifications.

| Security Item | Requirement | Implementation in SahanaMart | Verification & Audit Result |
|---------------|-------------|------------------------------|-----------------------------|
| **1. Query Parameterization** | Every SQL query MUST use `PreparedStatement` with `?` placeholders. Zero string concatenation allowed. | All queries in `UserDAOImpl`, `ProductDAOImpl`, `CartDAOImpl`, `OrderDAOImpl`, and `ReviewDAOImpl` use `conn.prepareStatement(...)` with typed parameter setters inside try-with-resources. | **PASS** — Static scan `grep -rn "Statement)" src/` confirms every statement executed via `PreparedStatement`. |
| **2. Password Hashing** | Store passwords using salted slow hash (`jBCrypt`). Never store plaintext; never log passwords. | `PasswordUtil` uses `org.mindrot.jbcrypt.BCrypt` with log rounds = 12. Password parameters are never printed in logs; passwords are removed from DTOs. | **PASS** — `UserResponseDTO` completely omits `passwordHash`. |
| **3. Protected Route Enforcement** | Enforce session authentication on all protected paths via `AuthFilter`. | `AuthFilter` intercepts `/buyer/*`, `/seller/*`, `/admin/*`, `/cart/*`, `/checkout/*`, `/reviews/add` and redirects unauthenticated users to `/login`. Validates role authorization (403 if unauthorized). | **PASS** — Automated filter tests and manual routes verification. |
| **4. Session Security** | Regenerate session ID upon login to prevent session fixation. Explicit session timeout. | `AuthServlet.java` calls `oldSession.invalidate()` and creates fresh session upon successful authentication. `web.xml` defines explicit 30-minute session timeout (`<session-timeout>30</session-timeout>`). | **PASS** — Session cookies set to `HttpOnly`. |
| **5. XSS Defense (Output Escaping)** | Escape all user-supplied input before rendering in web views. | All JSP templates strictly employ JSTL `<c:out value="..."/>` and `fn:escapeXml(...)` for dynamic rendering of user names, descriptions, comments, and query parameters. | **PASS** — Tested with `<script>alert(1)</script>` inputs; rendered safely as escaped text. |
| **6. Custom Error Pages** | Never expose server stack traces, database schema details, or file paths in HTTP error pages. | `web.xml` maps HTTP 404, HTTP 500, and `java.lang.Throwable` to styled error pages (`404.jsp` and `500.jsp`) without error details or stack traces. | **PASS** — Invalid URLs and runtime exceptions render clean branded error pages. |
| **7. Credential Protection** | Version control exclusion of passwords, API keys, and environment files. | `.gitignore` explicitly ignores `config.properties`, `.env`, `*.mv.db`, `*.trace.db`, `target/`, and sensitive IDE files. Template provided as `config.properties.example`. | **PASS** — Repository clean of credentials. |
| **8. HTTP Security Headers** | Protect against MIME sniffing, clickjacking, and reflected XSS. | `EncodingFilter` attaches `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, and `X-XSS-Protection: 1; mode=block` to every HTTP response. | **PASS** — Verified via response headers. |
